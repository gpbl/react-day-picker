# Accessible Date Pickers

DayPicker follows the [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) for date pickers, including features like keyboard navigation, focus management, and labeling.

Depending on your design, you might need to add more accessibility features. For example, when using [Input Fields](../guides/input-fields.mdx), there may be some limitations based on your accessibility goals. Keep up with best practices by following the [ARIA Patterns](https://www.w3.org/WAI/ARIA/apg/patterns/).

:::tip Accessibility Tips

- Test your date picker regularly with a screen reader to ensure accessibility.
- Use an `aria-live` region to announce when a date is selected, such as using the `footer` prop.
- Customize ARIA labels with the [`labels`](../api/react/interfaces/PropsBase.md#labels) prop for better user feedback.
- Maintain sufficient color contrast between text and background.
- Offer instructions for first-time users or those unfamiliar with the date picker.

:::

## Accessibility Props

| Prop Name         | Type                                      | Description                                                                                                                                                            |
| ----------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `labels`          | [`Labels`](../api/react/type-aliases/Labels.md) | Map of the ARIA labels used within DayPicker for better accessibility.                                                                                                 |
| `footer`          | `ReactNode` \| `string`                   | Add a footer to the calendar, which can act as a [live region](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Live_Regions) to announce updates. |
| `role`            | `application` \| `dialog`                 | Set the ARIA role for the container. Use `application` for a more interactive widget or `dialog` for a modal-like date picker.                                         |
| `aria-label`      | `string`                                  | The label to use for the container when a `role` is set, providing a descriptive text for screen readers.                                                              |
| `aria-labelledby` | `string`                                  | Reference another element that describes the calendar, such as a heading or external label, allowing assistive tech to announce that element as the calendar title.    |
| `autoFocus`       | `boolean`                                 | Autofocus the calendar when it opens, improving keyboard navigation.                                                                                                   |

### Autofocusing the Calendar {#autofocus}

DayPicker automatically manages focus when users interact with the calendar. To enhance accessibility, you can autofocus the calendar when it opens by using the `autoFocus` prop:

```tsx
<DayPicker mode="single" autoFocus />
```

## Focus Dates as Grid Cells

Use `dayInteraction="cell"` to focus the date cell directly. This avoids a nested date button, which can cause NVDA in Chrome to announce the same date twice.

```tsx
<DayPicker mode="single" dayInteraction="cell" />
```

The default, `dayInteraction="button"`, preserves the existing markup, labels, and custom `DayButton` components. Cell interaction works with single, multiple, range, and custom selection through `onDayClick`.

In cell mode:

- The cell handles focus, arrow navigation, clicks, and Enter/Space selection. Its content is a noninteractive `DayContent` component.
- The accessible date name comes from the displayed day number. Weekday headers are exposed to assistive technology, and each grid is associated with its month caption.
- Selection and today are conveyed through `aria-selected` and `aria-current="date"`, without repeating them in the default date name.
- Keyboard instructions are announced shortly after focus enters the dates. Moving between dates does not repeat the instructions.

Actual announcements depend on the browser and screen reader. Test this mode with the assistive technologies you support. This prop does not create a dialog or change the root `role`.

### Customize Labels and Instructions

An explicit `labels.labelGridcell` overrides the short date name in cell mode. If it is absent, an explicit `labels.labelDayButton` is also honored. An explicit `labels.labelGrid` overrides the month caption association. When `hideWeekdays` is set, or a date belongs to an adjacent month, the default date name includes the full date to retain context.

The default keyboard instructions are in English. Translate them with `labels.labelKeyboardHelp`, or supply `labelKeyboardHelp` in your locale's `labels` map. An explicit label prop takes precedence over the locale.

```tsx
<DayPicker
  mode="single"
  dayInteraction="cell"
  labels={{
    labelKeyboardHelp: () =>
      "Usa las flechas para navegar por las fechas. Pulsa Intro o Espacio para seleccionar.",
  }}
/>
```

Return an empty string from `labelKeyboardHelp` to disable the announcement when your application supplies its own instructions.

### Customize Cell Content

Use `components.DayContent` for decorations and noninteractive content in cell mode. Existing `components.DayButton` overrides apply only to button mode. The default content retains the `day_button` class and style slot; CSS selectors that target the `button` tag need a cell-mode equivalent.

Keep interactive controls out of `DayContent`. If you customize `Day`, compose the exported `Day` component and forward its props to preserve focus management and keyboard handlers. Custom `Weekdays` and `CaptionLabel` components should forward `aria-hidden` and `id`, respectively, to preserve header exposure and caption association.

## Keyboard Navigation

DayPicker supports keyboard navigation to make it easier for users to navigate the calendar. The following keys are supported:

| Keys                           | Function                             |
| ------------------------------ | ------------------------------------ |
| <kbd>Arrow Up</kbd>            | Move focus to the previous week.     |
| <kbd>Shift + Arrow Up</kbd>    | Move focus to the previous year.     |
| <kbd>Arrow Right</kbd>         | Move focus to the next day.          |
| <kbd>Shift + Arrow Right</kbd> | Move focus to the next month.        |
| <kbd>Arrow Down</kbd>          | Move focus to the next week.         |
| <kbd>Shift + Arrow Down</kbd>  | Move focus to the next year.         |
| <kbd>Arrow Left</kbd>          | Move focus to the previous day.      |
| <kbd>Shift + Arrow Left</kbd>  | Move focus to the previous month.    |
| <kbd>Page Up</kbd>             | Move focus to the previous month.    |
| <kbd>Page Down</kbd>           | Move focus to the next month.        |
| <kbd>Shift + Page Up</kbd>     | Move focus to the previous year.     |
| <kbd>Shift + Page Down</kbd>   | Move focus to the next year.         |
| <kbd>Home</kbd>                | Move focus to the start of the week. |
| <kbd>End</kbd>                 | Move focus to the end of the week.   |
| <kbd>Enter/Space</kbd>         | Select the focused day.              |
